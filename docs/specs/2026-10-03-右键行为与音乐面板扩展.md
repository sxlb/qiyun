# 右键行为、音乐面板扩展与图标探测修复 · 设计说明

日期：2026-10-03
状态：已实施

## 背景与问题

1. **音乐列表面板里的设置太薄**。面板设置原本只有三组：面板风格（跟随站点 + 3 套）、悬浮歌词字号（7 档）、三个显示开关。播放相关的行为（初始音量、播放模式、续播）与面板观感（不透明度、歌词聚焦、对齐）都没有出口。
2. **`https://blog.sxlb.xyz/` 拿不到网站图标**。后台「从网站获取」始终失败。实测该站 `/favicon.ico` 返回 404，第三方源里 favicon.im 返回 403、iowen 与 Google 直接不可达；而首页 HTML 明确声明了图标 `<link rel="icon" href="https://sxlbtuku1.oss-cn-hangzhou.aliyuncs.com/logo.jpg">`。根因是 `lib/favicon.ts` 的 `probeFavicon()` **只探测 `/favicon.ico` 与第三方服务，从不解析页面里的图标声明**，因此「图标托管在 OSS/CDN」这类站点必然探测失败。
3. **前端右键没有出口**。只有浏览器原生菜单一种行为，没有禁用或替换的选项。

## 目标

- 音乐面板设置补齐到「外观 + 播放行为 + 面板内容 + 系统集成」四类，且全部只影响本机。
- 图标探测能覆盖「根目录没有 favicon.ico、图标声明在 HTML 里」的站点。
- 右键行为后台三选一：原生 / 禁用 / 自定义站内功能菜单，菜单内容与本站能力对齐而非照搬通用导航菜单。

## 方案

### ① 图标探测：补上「页面声明」这一层

`probeFavicon()` 的优先级改为（前两步**并行**发起，声明命中时优先取声明）：

| 顺序 | 来源 | 说明 |
|---|---|---|
| 1 | 首页 HTML 声明的图标 | 解析 `rel` 为 `icon` / `shortcut icon` / `apple-touch-icon(-precomposed)` 的 `<link>`，按跳转后的最终地址补全相对路径，再逐个校验 |
| 2 | 站点自身 `/favicon.ico` | 没有声明时的通用约定 |
| 3 | 第三方图标服务 | favicon.im / icon.horse / xinac 图标库 / Google favicon（自定义源插在内置源之前） |

- 首页 HTML 最多读 256KB（图标声明必在 `<head>`），超出即截断并取消流。
- 声明地址可能指向别的域（如 OSS），因此仍然走 `fetchFollowingSafeRedirects` 的逐跳 SSRF 校验。
- 声明里常有多条（SVG → PNG → apple-touch-icon），并行校验后按声明顺序取首个可用，避免串行叠加等待。
- 失效源替换：`api.iowen.cn` 实测 DNS 已无法解析（连接直接失败），换为实测可达的 icon.horse / xinac 图标库。
- 上游再失效时无需改代码：后台「外部服务 → favicon 服务」可插一个自定义源到内置源之前。

相对路径必须用**跳转后**的地址做基准（`fetchWithSafeRedirects` 一并返回 `finalUrl`）：`https://example.com` → `https://www.example.com/` 这类跳转会让 `/icon.png` 被拼到错误的主机上。

### ② 音乐面板设置扩展（11 项，全部只存本机）

| 类别 | 新增项 | 默认 | 说明 |
|---|---|---|---|
| 播放行为 | 初始音量（滑杆 0-100） | 40 | 只在「还没有记住过音量」时生效；拖过播放器音量条后以实测值为准 |
| 播放行为 | 记住播放模式 | 开 | 落盘 `music-player-play-mode`，非法值回落列表循环 |
| 播放行为 | 续播上次曲目 | 开 | 只选中不播放，避免「一打开就有声音」的意外；id 不在歌单里则静默忽略 |
| 播放行为 | 关闭弹窗后继续播放 | 开 | 关闭时若为关，直接暂停并广播 `music-player-close` 复位动态标题 |
| 视觉细节 | 面板不透明度（滑杆 40-100） | 100 | 用 `color-mix` 只降**面板底色** alpha，不整块加 `opacity`（那会让文字一起变淡） |
| 视觉细节 | 歌词聚焦（非当前行模糊） | 开 | `opacity .55` + `blur(.5px)`，把视线收在当前句 |
| 视觉细节 | 歌词对齐（跟随风格 / 居中 / 左对齐） | 跟随风格 | 注入 `--mp-lyric-align` 覆盖三套风格各自的取值 |
| 视觉细节 | 歌单显示封面 | 关 | 默认关：多一张缩略图 = 多一轮第三方图片请求 |
| 交互 | 键盘快捷键（空格 / PgUp / PgDn） | 开 | 空格是通用键，被全站劫持并不总是用户想要 |
| 交互 | 系统媒体控制（锁屏 / 耳机） | 开 | 关掉后不再注册 MediaSession 的元数据与动作处理器 |
| 兜底 | 恢复默认设置 | — | 清掉全部本机键并广播 `music-prefs-reset` |

两个关键设计点：

- **键名收敛成一张表**（`MUSIC_PANEL_BOOL_KEYS` / `MUSIC_PANEL_VALUE_KEYS` / `ALL_MUSIC_LOCAL_KEYS`）。组件与 `useAudioPlayer` 都从表里取键，「恢复默认」也按同一张表清理 —— 漏一项的症状（设置完刷新就还原 / 重置后某项还留着）都很难查。
- **`prefsReady` 信号**。Provider 首帧读不到 localStorage（要保证 SSR 一致），偏好要等一个 effect 才可用。若不等这个信号就让 `useAudioPlayer` 用默认偏好初始化音量 / 播放模式，用户存好的设置会被默认值抢先顶掉。因此 `useAudioPlayer` 新增 `prefsReady`，未就绪时不做任何初始化、也不消耗「只应用一次」的标记。

### ②-b 设置视图改版（设置项涨到 15 项后）

一列铺开接近 20 行，面板必须整体滚动、把播放器和歌单一起挤下去 —— 这是「打开设置就拥挤」的直接原因。改法是两步：

1. **设置与播放器互斥**：点齿轮进入面板内的独立视图（只渲染设置），头部换成「设置 + 返回」，不再叠在播放器上。
2. **组内按「改的是什么」分三组**（而不是按控件类型）：`外观`（面板风格 / 面板不透明度 / 面板内显示曲目 / 歌单显示封面）、`歌词`（悬浮歌词字号 / 歌词对齐 / 顶部常驻歌词 / 面板内显示歌词 / 歌词聚焦）、`播放`（初始音量 / 记住播放模式 / 续播上次曲目 / 关闭弹窗后继续播放 / 键盘快捷键 / 系统媒体控制）。组内顺序统一为「先选择 / 拖动的项，后开关」。组内容给固定高度（`.mp-tabpanel`），切组时面板不跳高度；「恢复默认设置」放在组外，任何分组下都可见。

顺带修掉一个同源 bug：`parsePercentPref` 最初用 `Number(value)` 直接转换，导致 `null` / `""` 被算成 `0%`（`Number(null) === 0`）—— 与当年「首次访问音量被读成 0、喇叭显示静音且点不动」完全同类。现在显式把 `null` / `undefined` / 空白串判为「未设置」。

### ③ 右键三模式

新增 Profile 字段 `rightClickMode`（`default` / `disabled` / `menu`，枚举校验，默认 `default`）。前端 `components/home/ContextMenu.tsx` 只在非 `default` 时挂载，`default` 模式下**连 `contextmenu` 监听都不挂**。

放行规则（`shouldInterceptContextMenu`）——两种情况下不拦截：

- **表单控件 / 可编辑区域**：原生菜单里的粘贴、拼写检查不可替代，拦掉会直接影响可用性。
- **粗指针（触屏）**：长按会派发 `contextmenu`，拦掉会让移动端既没有原生菜单、也没法长按选词。

菜单条目按上下文裁剪，**不出现「点了没反应」的项**：

| 分组 | 条目 | 出现条件 |
|---|---|---|
| 链接 | 在新标签页打开 / 复制链接地址 | 右键落点在 `<a href>`（站内锚点、`javascript:`、`mailto:` 不算） |
| 选中 | 复制选中文字 / 搜索选中文字 | 右键时刻有非空选区（选区会先快照，动作执行时选区可能已变） |
| 音乐 | 播放 / 暂停、上一首、下一首 | 歌单已加载 |
| 音乐 | 打开音乐列表 | 恒定（歌单没配好时弹窗里会直接提示去后台填写） |
| 页面 | 换一张壁纸 | 仅 `landscape` / `anime`：必应每日一图当天是同一张、自定义地址是固定值，这两类点了不会有变化 |
| 页面 | 回到顶部 | 恒定 |
| 页面 | 打开命令面板 | 后台命令面板开关为开时 |
| 页面 | 复制本页链接 | 恒定 |

约定与联动：

- 音乐操作直接调 `useMusic()`（组件挂在 `MusicProvider` 内），不绕事件；「换一张壁纸」「打开命令面板」复用既有 window 事件约定（`wallpaper-next` / `open-command-palette`），菜单不反向持有这些组件的内部状态。
- 复制类条目先显示「已复制」再关闭，否则点了没有任何反馈；剪贴板优先 `navigator.clipboard`，失败（非安全上下文 / 权限被拒）回退临时 textarea + `execCommand`。
- 键盘可达：打开即聚焦菜单容器，Esc 关闭，方向键 / Home / End 移动高亮，Enter / 空格执行。
- 失焦即关：左键、滚动、缩放、切窗、在别处右键都会关闭；菜单内部的 `mousedown` 必须放行（否则 mousedown 先于 click 派发，会「先关菜单再丢点击」，表现为所有条目都点不动）。
- 视口边缘翻转：右下角右键时按测量结果把菜单收回屏内。
- 观感与站内玻璃卡片同语言（`backdrop-filter` + 强调色高亮），`z-index: 300` 高于音乐弹窗遮罩（200），`prefers-reduced-motion` 下不做入场动画。

**诚实的边界说明（已写进后台文案）**：「禁用右键」只是提高复制门槛，做不到内容保护 —— F12、地址栏直连、禁用 JS、抓包都能绕过；真要防抓取应靠服务端水印或权限控制。
