# 首屏加载与壁纸分流优化 · 设计说明

日期：2026-10-03
状态：已评审，待实施

## 背景与问题

1. **首屏约 7 秒才可用**。`LoadingScreen` 采用「双信号收起」：最短展示 800ms + 壁纸就绪（`background-ready`）都到齐才收起，另有 `SAFETY_MS = 7000` 兜底。冷缓存首次访问时，`/api/wallpaper` 会在服务端同步下载整图（超时 15s），下载完浏览器还要再下一遍全尺寸原图；`Background` 只有图片 `onload` 后才广播 `background-ready`。因此壁纸链路一超过 7 秒，加载动画必然卡满 7 秒 —— 用户观测到的"约 7 秒"正是该兜底被触发。
2. **加载动画观感差**。深色主题下三个同心环分别为白 / 灰 / 浅灰（`--loader-ring-1: #ffffff`），背景 `#1a1a2e`，观感是"黑底上几圈白线在转"；浅色主题背景为近白 `#eef2f8`，整体发白。整套动画未使用站点强调色（`--accent-color`）。
3. **壁纸未区分手机 / 电脑**。上游 `t.mwm.moe` 的约定是 `/pc` 为 PC 横图、`/mp` 为移动竖图，而当前 `anime` 源默认值指向 `/mp`，桌面端会拿到竖图。同时服务端缓存是单一池（`manifest.json` 条目无设备维度），即使配置了不同地址也可能串图。

## 目标

- 首屏最迟 3 秒进入页面，且背景从第一帧起就是真实图片。
- 加载动画使用站点强调色，深浅主题观感一致且不发白。
- 壁纸按设备分流：手机取竖图、电脑取横图，缓存不串图。

## 方案

### ① 首屏解绑

`LoadingScreen` 保留双信号机制，仅调兜底参数：

| 参数 | 现值 | 新值 |
|---|---|---|
| `MIN_SHOW_MS` | 800ms | 800ms（不变） |
| `SAFETY_MS` | 7000ms | 3000ms |
| CSS 纯 CSS 兜底 | 9s | 6s |

CSS 兜底必须晚于 JS 兜底：3s + 收起动画约 1.4s ≈ 4.4s，6s 满足。

`Background` 首帧立即铺一张内置默认壁纸（`lib/default-assets`，随包发布、零外部请求）作为底图，真实壁纸就绪后淡入覆盖。两条路径必须严格区分：

- `paintPlaceholder()` —— 仅铺底图，**不**广播 `background-ready`，因此不缩短动画的最短展示，保留仪式感。
- `applyBundledFallback()` —— 仅在真实壁纸彻底失败时调用，铺底图 **并**广播 `background-ready`，避免动画空等。

### ② 加载动画重做

- 主视觉：单道渐变弧（`conic-gradient` + `mask` 抠环），取 `var(--accent-color)`，缓速旋转 + 外发光。
- 氛围：弧后极光光晕呼吸（radial-gradient + 低频 scale/opacity）。
- 文字：站点名 `clip-path` 遮罩揭示，下方一条细进度线。
- 浅色主题：背景由近白 `#eef2f8` 改为低饱和暖灰；环不再使用深色硬边。
- 降级：`prefers-reduced-motion` 下只保留淡入，不做旋转与呼吸。
- 出场沿用现有左右分屏拉开 + 整体上移。

### ③ 壁纸按设备分流

**配置**（后台「外部服务」）：每个源拆分为电脑与手机两个地址。

| 源 | 电脑（横） | 手机（竖） |
|---|---|---|
| 风景 | `https://t.mwm.moe/fj`（沿用现值） | 新增字段，默认同 `/fj` |
| 动漫 | `https://t.mwm.moe/pc`（现值 `/mp` 有误，修正） | `https://t.mwm.moe/mp` |

**缓存分桶**：`manifest.json` 条目增加分池标签，风景 / 动漫用 `源:设备`（如 `anime:mobile`），与设备无关的源（必应）用 `shared`。读取规则：

- 优先取标签完全相同的条目；
- 标签为 `shared` 时，允许复用升级前的无标签历史条目；
- 标签为 `源:设备` 且本池为空时**不回退**，直接返回空让前端重新下载。

两处都取得比较严，各有原因。不回退：历史条目到底是什么来源、横竖已无从判断，把电脑横图塞给手机正是本次要修的问题，代价只是升级后各自的首次访问多下载一张。分池键必须带上来源而不只是设备：上游没有竖版风景源，风景端的手机地址实际仍是横图，若与动漫端共用 `mobile` 池，手机选「动漫」仍有概率抽到那张横图，等于没做到"手机只加载手机壁纸"。

轮换节流窗口（`lastRefreshAt` / `lastDownloadAt`）是全局共享的，不按池分开——小机器上「每个间隔只新增一张图」更省上游配额。

**设备判定**：客户端以视口宽度（`matchMedia("(max-width: 767px)")`）为最终依据，请求时带 `device=mobile|pc`；SSR 层用 UA 猜测一次，仅用于让 `<link rel="preload">` 预加载对图，客户端结果优先。

**数据迁移**：新增 Profile 字段为加列且带默认值，生成一个 Prisma migration；容器启动执行 `prisma migrate deploy` 自动应用，不影响现有 `prod.db`。

### ④ 社交链接预设

新增 `lib/social-presets.ts`（名称 / 图标 / 地址前缀 / 悬停提示），`LinksPanel` 增加可选 `presets` 入参并渲染为图标条，点击后追加一行并展开。`LinksManager` 仅在「社交链接」子 Tab 传入。

内置：GitHub、Bilibili、微博、知乎、X、Telegram、Email、QQ、微信、抖音、小红书、网易云音乐。

## 影响范围

- 首屏：`components/home/LoadingScreen.tsx`、`components/home/Background.tsx`、`app/globals.css`
- 壁纸：`prisma/schema.prisma` + 迁移、`lib/external-api.ts`、`lib/wallpaperCache.ts`、`app/api/wallpaper/route.ts`、`app/page.tsx`、`app/home-data.ts`、`components/admin/ProfilePanel.tsx`、字段白名单
- 后台：`components/admin/LinksPanel.tsx`、`components/admin/LinksManager.tsx`、`lib/social-presets.ts`

## 验收标准

- 冷缓存首次访问最迟 3 秒进入页面，且第一帧背景为真实图片。
- 动画改色后深浅主题均不发白，`prefers-reduced-motion` 下不旋转。
- 手机请求只取手机图、电脑只取电脑图；历史无标记缓存仍可被使用但不跨设备。
- 社交预设点击一次即生成填好名称 / 图标 / 地址前缀的行。
- `typecheck` / `lint` / `test` / `build` 全绿。
